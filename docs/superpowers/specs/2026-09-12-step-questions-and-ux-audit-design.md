# Step 问题归位与操作体验优化设计

## 背景与目标

当前 Step 页面把 Checklist、原有 Questions 以及新增的“完成说明”呈现为三套并行内容。新增的 `responseRequired / responsePrompt / response` 不属于正确业务模型，既重复采集信息，也把“完成动作”和“回答问题”混为一谈。本次修改恢复单一答案来源：Checklist 只表达执行状态，Questions/Answers 承载文字输入，并在同一张 Checklist 卡片内按先检查、后回答的顺序展示。

本次同时修复截图中暴露的按钮布局问题，并针对核心项目流程进行功能、页面、UI 与可访问性自检。用户确认 P0、P1、P2 全部在本次交付实现；实施拆为“Step 与数据修正”“全局流程与界面优化”“备份恢复与完整验证”三个连续里程碑。

## 选定方案

采用“同一卡片双分区”方案：Checklist 卡片上半部分保留检查项，下半部分通过分隔线展示“需要回答的问题”。不为每条 Checklist 增加输入框，也不建立强制的一对一关系。这样既保持任务顺序，又避免每个检查项展开后造成页面碎片化。

### Step 页面结构

1. 页面头部、说明卡片保持现有主题。
2. Checklist 卡片上半区只显示检查项和完成状态，点击文字或复选图标均可切换。
3. 卡片下半区显示 Questions。每个问题包含标题、可选提示和输入框，继续使用 `step.answers[questionId]` 自动保存。
4. 不再显示独立的“需要回答的问题”大区块，也不再显示“填写完成说明”。
5. 完成 Step 时不以 Checklist 的文字答案做校验；现有 Questions 可为空，完成约束仍由用户、阶段 Todo、成果与 Stage Gate 控制。
6. 修正底部“上一步”按钮箭头方向。

## 数据模型与迁移

### 数据模型

- `PlaybookStepDef.checklist` 恢复为 `{ id, text }[]`。
- `ProjectChecklistItem` 恢复为 `{ id, text, done }`。
- Questions 和 `answers` 继续作为唯一文字回答模型。
- 删除默认 Playbook 的 Checklist 回答规则和 Playbook 编辑器中的“需要说明”配置。

### 无损迁移

数据版本升级到 v3。迁移时遍历现有项目：

- 若旧检查项存在非空 `response`，且当前 Step 尚无相同内容的答案，则把内容迁入一个稳定的兼容问题答案；兼容问题标题使用旧 `responsePrompt`，没有提示时使用检查项文本。
- 已有 Questions/Answers 绝不覆盖。
- 若同一 Step 有多个旧说明，分别生成稳定 ID，避免丢失。
- 完成迁移后从内存数据中移除 Checklist 的旧回答字段；保存后的 JSON 只保留新结构。
- v1、v2 数据都可直接迁移到 v3。

## Questions 完整性检查

检查默认 Playbook 的 8 个阶段、32 个 Step。原则是“问题用于推动思考或记录结果，不机械复制 Checklist 文案”。现有问题语义已覆盖大多数检查项，本次仅补充明确缺失且无法由已有问题回答覆盖的关键内容：

- `op_s2`：增加“一句话产品机会描述是什么？”
- `op_s3`：增加“用户真正需要解决的核心问题是什么？”

其余 Step 保留现有综合问题，避免把 88 个检查项扩展为 88 个表单字段。兼容迁移产生的问题只存在于对应旧项目，不写入默认方法论。

## 按钮与通用组件修复

- 通用 Button 增加 `whitespace-nowrap`、`flex-shrink-0` 和稳定行高，防止“添加”等短按钮被压成竖排。
- Claims 新增行的输入框增加 `min-width: 0`，按钮保持固定内容宽度；窄窗口下允许整行换行为上下布局。
- 所有本次触达的图标按钮补充可读 `aria-label` 和可见焦点态。
- Modal 增加 `role="dialog"`、`aria-modal`、标题关联、打开后初始聚焦、Tab 焦点循环和关闭后焦点恢复。
- Toast 容器增加 `aria-live`，保存、失败等状态可被辅助技术感知。

## 流程自检与本次修复范围

### P0：本次必须修复

1. Step 重复答案模型和错误交互。
2. Claims “添加”按钮换行。
3. 项目报告导出弹窗目前只有“生成并导出”，实际上强制启用 AI；增加“直接导出”和“AI 总结并导出”两个明确操作，AI 未配置时仍可导出。
4. 上一步箭头方向错误。

### P1：本次实现

1. 通用按钮不换行、窄窗口自适应。
2. Modal 键盘与语义支持。
3. Toast 状态播报。
4. 删除 Claim/Evidence 的图标按钮始终保留可发现性，增加标签；删除 Claim/Evidence 保持直接删除，项目删除继续二次确认。
5. 自动保存增加轻量“保存中 / 已保存”状态，避免用户无法判断输入是否落盘。
6. 锁定阶段的“阶段决策”按钮旁显示无法操作的原因。

### P2：本次实现

1. 统一术语为“中文主名称 + 英文括注”：项目组合、执行步骤（Steps）、假设（Claims）、证据（Evidence）、资料（Artifacts）、设置。报告保持专业英文缩写，但首处同时给出中文名称。
2. 阶段页顶部增加“推进摘要”，集中显示步骤、阶段 Todo、必要成果、证据、退出条件五组进度，以及当前最先需要处理的缺口；原有明细区继续保留，避免丢失编辑入口。
3. 项目组合页增加搜索框，按项目名称、描述、当前阶段和状态实时过滤；无结果时显示清除搜索入口。记录最近打开的 5 个项目，但不改变用户拖动后的侧边栏顺序；项目组合页以快捷入口展示最近打开。侧边栏项目区显示已打开数量，在多项目时提供“全部折叠”，并保持独立滚动以处理溢出。
4. 设置页增加完整备份与恢复：
   - 创建备份时选择父目录，生成带时间戳的备份文件夹，复制 `data.json` 与 `artifacts` 目录。
   - 备份包含 AI 设置，因此界面明确提示可能含 API Key，用户应妥善保管。
   - 恢复时选择备份中的 `data.json`，验证基本结构和版本；恢复前在应用数据目录自动创建 `before-restore` 安全副本。
   - 恢复同时替换配套 `artifacts`，成功后重新加载内存数据；失败时保留当前数据并给出可理解错误，不执行半恢复。
5. 增加专门的体验回归：键盘可完成主要页面导航和弹窗操作；200% 缩放等效窄视口下按钮不竖排、关键操作不溢出；核心状态使用语义标签与 live region。自动化覆盖可验证行为，打包后人工检查 Windows 缩放与屏幕阅读器读序，并明确记录自动化不能证明完整 WCAG 合规。

## 报告与 AI

项目报告和 AI 上下文移除 Checklist `response`，继续读取 Questions/Answers。迁移出的兼容问题也会自然进入报告和 AI 上下文，因此旧内容不会丢失。

## 测试与验收

- 数据迁移测试：v2 说明迁入 Questions/Answers、已有回答不覆盖、旧字段移除、v1 直升 v3。
- Step 页面测试：同一卡片双分区、无“填写完成说明”、新增关键问题可输入并自动保存、上一步箭头正确。
- Button/Claims 测试：按钮不换行，Claims 在窄布局下不出现竖排文本。
- 导出测试：直接导出传 `withAiSummary: false`，AI 导出传 `true`。
- Modal/Toast 可访问性测试：dialog 语义、焦点进入与返回、Escape、Tab 循环、live region。
- 搜索与最近打开测试：多字段过滤、清除空结果、最多 5 项且不改变侧边栏排序、全部折叠。
- 阶段摘要测试：五类进度和首要缺口准确。
- 备份恢复测试：完整复制、结构校验、恢复前快照、失败不修改当前数据、成功后重新加载。
- 术语与窄视口测试：中文主名称存在，关键按钮具有不换行和防收缩样式。
- 完成 `pnpm typecheck`、`pnpm test`、`pnpm build`，再进行代码审查。

## 审计证据限制

当前视觉证据来自用户本轮提供的 Step 与 Claims 两张截图；已确认重复输入、按钮换行和信息层级问题。Electron 自动截图端点在当前执行环境被策略阻止，因此其他页面属于代码与交互逻辑级审计，不能据此声称完成像素级或完整 WCAG 合规验证。最终交付会明确区分已测试行为、截图确认问题和后续需要人工视觉检查的项目。
