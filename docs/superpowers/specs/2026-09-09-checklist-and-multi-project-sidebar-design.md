# Checklist 回答与多项目侧边栏设计

## 目标

补齐 Checklist 条目的回答入口，并审计默认生命周期中所有相同缺口；将侧边栏升级为可持久化的多项目工作区，支持多个项目并列、独立折叠、八阶段导航、右键移出和拖拽排序；同时修正 AI 测试连接对空文本响应的误判。所有新增界面继续使用现有深墨侧边栏、暖纸内容区和靛蓝主色。

## 范围与非目标

本次修改覆盖 Step Checklist 数据、默认 Playbook、旧数据兼容、Step 页面、侧边栏工作区状态和 AI 连接检测。右键“从侧边栏移除”只改变本机 UI 工作区，不删除、不暂停、不修改项目，也不改变项目组合排序。多项目“同时打开”指多个项目同时保留在侧边栏并可快速切换，不创建多个 Electron 窗口。阶段本身不可拖动，项目组合页的业务排序规则不变。本轮不实施此前讨论的 portable 启动方式调整。

## Checklist 数据模型与审计

`PlaybookStepDef.checklist` 条目增加可选字段 `responseRequired?: boolean` 和 `responsePrompt?: string`；`ProjectChecklistItem` 增加相同元数据以及 `response?: string`。默认 Playbook 的全部 32 个 Step、90 余个 Checklist 条目逐项审计：需要用户描述、定义、列出、分析、说明、总结、记录或给出文字成果的条目标记为必答，并配置具体问题式提示；纯执行动作（例如完成访谈、运行流程、生成版本、提交已有交付物）保持可直接勾选。不得根据中文关键词在运行时猜测必答性。

项目创建时把定义元数据复制进工作流快照，并把 `response` 初始化为空字符串。Playbook 编辑器保留既有条目 ID 和回答元数据；新增条目默认不强制回答，编辑界面提供“需要完成说明”和提示语配置。删除或重新排列条目时不能把其他条目的元数据按数组下标错配。

## 旧数据兼容

数据版本从 1 升到 2。迁移只补充字段，不覆盖 `done`、现有问题答案或其他项目快照内容。内置默认 Playbook 与基于它创建的项目使用稳定 Checklist ID，从代码中的显式回答规则表补齐 `responseRequired` 和 `responsePrompt`；其他自定义 Playbook/项目的旧条目默认 `responseRequired=false`、`response=''`，避免升级后阻断已完成工作。迁移后原子写回数据文件，并保留现有损坏备份机制。

## Step 交互与保存

Checklist 卡片中的必答条目显示“填写完成说明”入口；展开后在条目下方呈现与“需要回答的问题”一致的圆角文本框、明确提示语和自动保存状态。输入内容保存在条目自身的 `response`，复用现有 450ms 防抖保存。用户点击未完成的必答条目时，若回答为空则展开并聚焦输入框，显示轻量错误提示，不允许勾选；填写非空内容后才可勾选。已完成条目允许取消勾选，回答保留。完成整个 Step 前再次验证所有已勾选的必答条目均有回答，防止绕过 UI。

现有“需要回答的问题”继续保留，它承担 Step 层面的引导；Checklist 回答承担单项验收证据。AI Step 辅助上下文与项目报告需包含 Checklist 回答，使填写内容真正进入后续成果，而不是只存在于界面。

## 多项目侧边栏状态

新增独立的 renderer 工作区 store，使用版本化 `localStorage` 键保存：

```ts
interface SidebarWorkspaceV1 {
  version: 1
  projectIds: string[]
  expandedProjectIds: string[]
}
```

进入任何 `/project/:projectId` 路由时，如果项目存在则自动追加到 `projectIds`；创建项目成功并跳转时自然触发同一逻辑。加载时过滤已被真正删除的项目 ID，并去重。状态只保存项目 ID，不复制名称或阶段数据，展示内容始终来自最新 `AppData`。

## 侧边栏交互

主导航下显示“已打开项目”。每个项目标题行包含折叠箭头、项目名和当前阶段状态；当前路由项目使用现有靛蓝/白色高亮。展开后按 `order` 显示八个阶段，使用已完成、当前、未开始状态点；点击阶段进入该项目阶段页，锁定阶段仍可查看但不改变业务状态。

项目标题支持 HTML5 拖放。开始拖动时立即从 `expandedProjectIds` 移除被拖项目，缩小拖动占位；经过目标项目时显示细线落点；放下后只更新 `projectIds` 顺序并持久化。键盘用户可通过项目标题旁“上移/下移”菜单完成等价排序。拖动结束但未落在有效目标时保持原顺序。

项目标题右键打开使用 Portal 的上下文菜单，唯一破坏性外观操作为“从侧边栏移除”，但文案和行为均明确不删除项目。移除当前路由项目后内容页保持不变；再次访问该项目时自动重新加入。菜单需复用现有视口翻转、滚动跟随和点击外部关闭逻辑。

## AI 连接检测

把传输请求与业务文本校验分开。测试连接保存当前设置后发送非流式最小对话请求；HTTP 2xx、JSON 可解析且包含非空 `choices` 数组，即判定 API 地址、鉴权和模型调用链已联通。若 `message.content` 有值，显示模型返回摘要；若内容为空但响应结构有效（包括只有 `reasoning_content` 的情况），显示“连接成功，服务已响应但未返回文本”。HTTP 4xx/5xx、超时、无效 JSON 或缺少 `choices` 仍判定失败。阶段审查、Step 辅助和项目总结继续要求非空最终文本。

## 错误处理与可访问性

本地工作区 JSON 损坏时回退为空状态，不影响项目数据库。右键菜单、折叠按钮、拖动替代操作和回答输入均提供可访问名称；菜单支持 Escape 关闭。保存失败沿用全局错误 Toast，并保留用户当前输入以便重试。旧项目迁移或侧边栏过滤不允许删除领域对象。

## 测试与验收

自动化测试覆盖：默认规则表中的已知必答/纯动作条目；创建项目复制回答元数据；v1 到 v2 迁移不覆盖既有数据；必答条目空回答不能完成、填写后可完成并自动保存；AI 上下文包含回答；项目访问自动加入、去重、过滤失效 ID、右键移出不调用删除 API；项目独立折叠；拖动开始自动折叠、有效放置更新并持久化顺序、无效放置保持顺序；八阶段链接和当前状态；AI 正常文本、2xx 空文本、HTTP 错误、无效响应四个分支。最终必须通过 `pnpm test`、`pnpm typecheck`、`pnpm build`，并在生产构建中人工检查 Step 输入、侧边栏拖放和上下文菜单。
